# Delivery roadmap

Complete one phase's acceptance review before beginning dependent product work. Phases are release milestones in this repository; they are not claims that implementation is already complete.

| Repository phase | Source roadmap mapping | Deliverable | Exit gate |
| --- | --- | --- | --- |
| 1 | Source Phase 0 and Phase 1 | Foundation, auth, profile, content schema, Python UI proof | Persisted candidate/admin flow with verified access isolation |
| 2 | Source Phase 2 | Grounded Company Hub and complete learning/practice loop | Diagnostic to roadmap to sandbox practice to evidence-based revision |
| 3 | Source Phase 3 | Strict OA, objective scoring, unlock rules | Server-authoritative timing and reproducible result/unlock under retry and reconnect |
| 4 | Source Phase 4 | Multi-round interview simulations | Adaptive, bounded follow-ups and rubric feedback linked to transcript/code evidence |
| 5 | Source Phase 5 | Tracker, readiness, stable reports, accessibility and beta hardening | Complete journey with reproducible dimensions and report snapshot |
| 6 | Source Phase 6 | Soft launch, feedback and quality operations | Measured user outcomes, cost/error monitoring and repeatable releases |

## Phase 3 subtasks

- [ ] P3-01 Version assessment blueprints, frozen question sets and retry policy.
- [ ] P3-02 Implement server-authoritative start/deadline, autosubmit and reconnect behavior.
- [ ] P3-03 Block tutor, hints and solution access server-side during active strict assessments.
- [ ] P3-04 Score hidden-test evidence deterministically; handle late submissions and runner outages.
- [ ] P3-05 Add visible, versioned simulation thresholds and evidence-linked interview unlocks.
- [ ] P3-06 Validate Python UI capability and implement only supportable, consented integrity signals; offer accommodations and document limitations.
- [ ] P3-07 Verify duplicate requests, clock tampering, cross-device tutoring attempts and corrected-score recalculation.

## Phase 4 subtasks

- [ ] P4-01 Technical interview state machine: clarify, approach, implement, test and reflect.
- [ ] P4-02 Dynamic follow-up objectives, competency coverage, repetition limits and time budget.
- [ ] P4-03 Behavioral and managerial rounds with transcript evidence and structured rubrics.
- [ ] P4-04 Lightweight HR practice using only candidate-supplied career facts.
- [ ] P4-05 Reviewed company behavioral-framework mapping and post-session coaching.
- [ ] P4-06 Evaluate role adherence, fabricated evidence, answer leakage and provider interruption recovery.

## Phase 5 subtasks

## Phase 6 subtasks

- [ ] P6-01 Limited beta onboarding and consented feedback collection.
- [ ] P6-02 Measure activation, useful practice completion, retention, AI cost and failure rates.
- [ ] P6-03 Establish content review cadence and prompt/model release evaluations.
- [ ] P6-04 Prioritize demonstrated weaknesses before widening scope.

## Later backlog

Multi-company expansion, deep system-design interviews, opt-in notifications, subscriptions/entitlements, mobile experiences and institutional features require separate plans. Specialist model evaluation or fine-tuning requires lawful opt-in data and evidence of benefit over the baseline; freshness-sensitive company information remains in retrieval. Other candidate programming languages are excluded under the current Python-only scope unless the user changes it.

The source estimates roughly 20–25 weeks before ongoing soft launch. This is contextual only: Python UI adaptation and infrastructure choices change effort, and no delivery date is committed here. Split each task into small sessions after confirming available development hours.
